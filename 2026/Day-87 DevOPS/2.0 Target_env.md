# 2.0 Deploying Code on Virtual Machine, Containers, Kubernetes Cluster

**NIT Academy | DevOps Project — CI/CD Deployment Roadmap**

## 🎯 Learning Objectives

By the end of this lesson, students should be able to:

- Identify the three target environments for deploying the Java application: a virtual machine, a Docker container, and a Kubernetes cluster.
- Explain how GitHub, Jenkins, Maven, Tomcat, Docker, Ansible, and Amazon EKS work together.
- Describe the setup and integration steps for each stage of the CI/CD project.
- Understand how the deployment process evolves from a single VM to container orchestration.

## 1. Introduction: Three Deployment Environments

Throughout this DevOps project, we will build and deploy the same application to three types of target environments:

1. **Virtual Machine (VM):** Deploy the application to an Apache Tomcat server running on a VM.
2. **Docker Container:** Package and run the application in a Docker container.
3. **Kubernetes Cluster:** Deploy and manage the containerized application on Kubernetes using AWS Elastic Kubernetes Service (EKS).

We will build the project incrementally. Each stage reuses tools and skills from the previous stage.

```text
                      Java Application Source Code
                                  |
                               GitHub
                                  |
                               Jenkins
                                  |
                                Maven
                                  |
                          Build Artifact (WAR)
                                  |
                  +---------------+---------------+
                  |               |               |
                  v               v               v
             VM + Tomcat     Docker Container   Kubernetes (EKS)
                Stage 1         Stages 2–3          Stage 4
```

> **Teaching note:** The diagram shows the three deployment destinations. They are introduced sequentially, not necessarily deployed simultaneously.

## 2. Stage 1 — Deploying to a Virtual Machine with Tomcat

**Tools:** Git, GitHub, Jenkins, Maven, Apache Tomcat

We begin without an existing CI/CD environment. Our first task is to build the infrastructure and connect the tools.

### Implementation steps

1. Set up a **Jenkins server**.
2. Install and configure **Git** and **Maven**.
3. Set up an **Apache Tomcat server** on the target VM.
4. Integrate **GitHub, Maven, and Tomcat** with Jenkins.
5. Create a **Jenkins CI/CD job** to retrieve, build, and deploy the application.
6. **Test the deployment** to verify the application works on Tomcat.

### CI/CD workflow

```text
Developer -> Git -> GitHub
                       |
                       v
                    Jenkins
                       |
                       v
                 Maven Build
                       |
                       v
                Java WAR Artifact
                       |
                       v
                Tomcat Server (VM)
                       |
                       v
                 Application Test
```

**What students should understand:** Jenkins retrieves code from GitHub, Maven builds the Java application and produces the deployable artifact, and the pipeline deploys that artifact to Tomcat.

## 3. Stage 2 — Deploying to a Docker Container

**Tools:** GitHub, Jenkins, Maven, Docker

After completing the VM deployment, we retain our existing GitHub, Jenkins, and Maven environment. The next task is to set up Docker and change the deployment target.

### Implementation steps

1. Set up a **Docker environment** on a Docker host.
2. Write a **Dockerfile** describing the application image.
3. Build a **Docker image** and create a **container**.
4. Integrate the **Docker host with Jenkins**.
5. Create a **Jenkins CI/CD job** to build and deploy the application in a container.
6. Test the running container and application.

### CI/CD workflow

```text
GitHub -> Jenkins -> Maven -> Application Artifact
                                      |
                                      v
                                  Dockerfile
                                      |
                                      v
                                 Docker Image
                                      |
                                      v
                             Docker Container (Host)
                                      |
                                      v
                               Application Test
```

**Key distinction:** A Docker image is the packaged blueprint; a container is a running instance of that image.

## 4. Stage 3 — Deploying to Docker with Ansible

**Tools:** GitHub, Jenkins, Maven, Ansible, Docker

We now introduce **Ansible** to automate container image creation and deployment. Jenkins orchestrates the pipeline, while Ansible runs the deployment tasks on the appropriate hosts.

### Implementation steps

1. Set up an **Ansible control node**.
2. Configure Ansible access to the **Docker host**.
3. Write an **Ansible playbook to build the Docker image**.
4. Write an **Ansible playbook to create and run the container**.
5. Integrate **Ansible with Jenkins**.
6. Create a **Jenkins CI/CD job** that builds the Java application and invokes Ansible for Docker deployment.
7. Optionally publish the built image to **Docker Hub** so it can be retrieved by other environments.

### CI/CD workflow

```text
GitHub -> Jenkins -> Maven -> Application Artifact
                       |
                       v
                 Ansible Playbooks
                       |
              +--------+--------+
              |                 |
              v                 v
        Build Docker Image   Deploy Container
              |                 |
              v                 v
        Docker Hub*         Docker Host

* Image push to Docker Hub is part of the proposed workflow.
```

**Important clarification:** Maven builds the Java application artifact. Docker builds the container image. Ansible automates those tasks and deployment; it does not replace Maven as the Java build tool.

## 5. Stage 4 — Deploying to Kubernetes on AWS EKS

**Tools:** GitHub, Jenkins, Maven, Ansible, Docker, Kubernetes, AWS EKS

Finally, we replace the standalone Docker deployment target with a Kubernetes cluster. We reuse the existing CI/CD environment and add Kubernetes infrastructure and deployment configuration.

### Implementation steps

1. Set up a Kubernetes cluster on AWS using **Amazon Elastic Kubernetes Service (EKS)**.
2. Write Kubernetes **Pod**, **Deployment**, and **Service** manifests.
3. Configure Ansible access to the **Kubernetes cluster**.
4. Write **Ansible playbooks** to apply Deployments and Services.
5. Create a **Jenkins CI/CD job** to build the application and trigger Kubernetes deployment through Ansible.
6. Verify the application is running and accessible through the configured Service.

### CI/CD workflow

```text
GitHub -> Jenkins -> Maven -> Java Artifact
                       |
                       v
                Build Docker Image
                       |
                       v
                Container Registry
                       |
                       v
                Ansible Playbook
                       |
                       v
                 AWS EKS Cluster
                       |
                       v
             Kubernetes Deployment
                       |
                       v
                Pods + Service
                       |
                       v
                Application Test
```

> **Teaching note:** In practice, a Kubernetes Deployment manages Pods, and a Service provides stable access to them. A standalone Pod manifest is useful for learning, but a Deployment is the normal application-management resource.

## 6. Comparing the Four Project Stages

| Stage | Target environment | Primary tools | Main learning outcome |
|---|---|---|---|
| 1 | Virtual machine running Tomcat | GitHub, Jenkins, Maven, Tomcat | Build and deploy a Java application to a VM |
| 2 | Docker container | GitHub, Jenkins, Maven, Docker | Build an image and run the application in a container |
| 3 | Docker container with automated deployment | GitHub, Jenkins, Maven, Ansible, Docker | Automate image creation and container deployment |
| 4 | Kubernetes cluster on AWS EKS | GitHub, Jenkins, Maven, Docker, Ansible, Kubernetes, AWS | Automate deployment to a container orchestration platform |

## 7. Responsibilities of Each Tool

| Tool | Role in the project |
|---|---|
| **Git** | Track local source-code changes |
| **GitHub** | Host the shared source-code repository |
| **Jenkins** | Coordinate CI/CD pipeline jobs |
| **Maven** | Compile, test, and package the Java application |
| **Tomcat** | Run the Java web application on the VM |
| **Docker** | Build container images and run containers |
| **Ansible** | Automate configuration and deployment tasks |
| **Docker Hub / Registry** | Store and distribute container images |
| **Kubernetes** | Manage containerized applications through Deployments, Pods, and Services |
| **AWS EKS** | Provide a managed Kubernetes control plane on AWS |

## 9. Common Mistakes to Avoid

- Confusing **Maven's Java build** with **Docker's image build**.
- Treating an **image** as if it were already a running container.
- Assuming Jenkins must host the deployed application; it usually orchestrates deployment to a separate target.
- Assuming Ansible itself is a container runtime; it automates tasks on target systems.
- Deploying to Kubernetes without providing a registry-accessible container image.
- Confusing a Kubernetes **Pod** with a **Deployment** or **Service**.
- Forgetting to test the application after deployment.

## 📖 Key Takeaways

- The project progresses from **VM deployment** to **Docker deployment** to **Ansible automation** and finally **Kubernetes orchestration**.
- GitHub stores source code, Jenkins coordinates the pipeline, and Maven builds the Java application.
- Tomcat is the initial deployment target; Docker and Kubernetes are introduced in later stages.
- Ansible automates deployment actions and integrates with Jenkins.
- AWS EKS provides the managed Kubernetes environment used in the final stage.

## ⭐ Golden Rule

**Build once with a repeatable process, automate the deployment, and verify the application in every target environment.**
